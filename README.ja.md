# reverse-proxy

Rustで実装したHTTPリバースプロキシです。ルートごとの複数バックエンド・2種類の負荷分散アルゴリズム・定期的なヘルスチェック・グレースフルシャットダウンに対応しています。

## 機能

- **負荷分散アルゴリズム**：ラウンドロビンまたは最小接続数をルートごとに設定できます。
- **ヘルスチェック**：バックエンドを定期的に確認し、異常なバックエンドは自動的にスキップします。復旧したバックエンドはプールに戻されます。
- **最長プレフィックスルーティング**：複数ルートに対応し、各ルートが独自のバックエンドと負荷分散アルゴリズムを持ちます。
- **グレースフルシャットダウン**：処理中のリクエストを設定可能なタイムアウトまで待ってから終了します。
- **HTTP仕様への準拠**：ホップバイホップヘッダーの除去・`X-Forwarded-For`チェーンへの追記・`Host`ヘッダーの書き換えを行います。

## 設計

**接続数の追跡**：`Backend`構造体はアトミックなヘルスフラグとアクティブな接続数カウンターを持ちます。`BackendGuard`はRAIIガードで、取得時にカウンターをインクリメントし、ドロップ時にデクリメントします。これにより、最小接続数アルゴリズムはリクエストの成否によらず常に正確な接続数を参照できます。

**負荷分散の抽象化**：`LoadBalancer`は、`RoundRobin`と`LeastConnections`の両方が実装しているトレイトです。新しいアルゴリズムを追加する際、プロキシやルーティングのロジックを変更する必要はありません。

**ヘルスチェック**：各ルートは、設定された間隔でバックエンドを確認する独立したTokioタスクを起動します。ヘルス状態はアトミックに書き込まれるため、プロキシはバックエンドの状態確認にロックを必要としません。

**グレースフルシャットダウン**：`SIGINT`または`SIGTERM`（非Unix環境ではCtrl+Cのみ）はブロードキャストチャネルのフラグをセットし、サーバーループは新しい接続を受け付ける前にこれを確認します。ドレイン処理には`tokio::time::timeout`によるタイムアウトが設けられています。処理中のリクエストが設定タイムアウトを超えた場合、プロキシは警告をログに出力して終了します。

## 設定

設定はTOMLファイルで記述します。デフォルトでは作業ディレクトリの`reverse-proxy.toml`を読み込みますが、`REVERSE_PROXY_CONFIG_PATH`環境変数で上書きできます。

```toml
listen_addr = "127.0.0.1:3000" # リバースプロキシがリッスンするアドレス
shutdown_timeout = 10 # シャットダウン時に処理中のリクエストを待つ秒数

[[routes]]
prefix = "/"
backend_addrs = ["127.0.0.1:8001", "127.0.0.1:8002", "127.0.0.1:8003"]
health_check = { path = "/health", interval_secs = 10 }
balancing_algorithm = "round_robin"

[[routes]]
prefix = "/api"
backend_addrs = ["127.0.0.1:9001"]
health_check = { path = "/ping", interval_secs = 5 }
balancing_algorithm = "least_connections"
```

ルートはパスのプレフィックスで照合され、最も長く一致したルートが選択されます。各ルートは起動時に少なくとも一つのバックエンドが必要です。全バックエンドが異常状態のルートへのリクエストに`503 Service Unavailable`を返し、どのルートにも一致しないリクエストには`404 Not Found`を返します。

## 使い方

### ビルドと実行

Rustのインストール方法は[こちら](https://www.rust-lang.org/ja/tools/install)を参照してください。

```sh
cargo run
```

ログレベルは`RUST_LOG`環境変数で設定できます（例：`RUST_LOG=debug cargo run`）。デフォルトレベルは`info`です。

### 簡単なデモ

[Python](https://www.python.org/downloads/)と[Just](https://github.com/casey/just)が必要です。

```sh
just
```

ポート8000でPythonの`http.server`を、ポート3000でプロキシを起動し、プロキシ経由でテストリクエストを送信します。

## テスト

```sh
cargo test
```

ルート解決、ヘッダー処理、ヘルスチェックの検知と復旧、負荷分散アルゴリズム、グレースフルシャットダウン、シャットダウンタイムアウトのテストが含まれます。

## CI

`main`ブランチへのプッシュおよびプルリクエスト時に、GitHub Actionsでテスト・リント・フォーマット確認が実行されます（[`.github/workflows/ci.yml`](.github/workflows/ci.yml)参照）。
